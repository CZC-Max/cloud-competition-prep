# 每日收尾流程（固定动作，不用提醒）

> 每天训练结束后必做的四步。**作品集 = 备赛的副产品**，靠的就是这个闭环每天转一圈。

## 流程总览

```
① 沉淀：把当天踩的坑写进仓库 docs/
② 总结：产出 docs/daily/YYYY-MM-DD.md（一句话总结 + 里程碑 + 坑 + 明日计划）
③ 存档：更新工作区 memory（当天工作日志）
④ 发布：git add / commit / push 给用户执行 → GitHub 绿格子 +1
```

---

## ① 沉淀（最重要的一步）

当天踩到的每个坑，按这个四段模板落到对应文档：

```markdown
| 项 | 内容 |
|---|---|
| **现象** | 屏幕上的真实报错原文 |
| **原因** | 为什么会这样 |
| **解法** | 当场是怎么修的（命令） |
| **考场启示** | 这条经验在考场上怎么用 / 考的是哪个点 |
```

**落点规则**：

| 类型 | 写进哪里 |
|---|---|
| 技术模块操作（K8S / CEPH / OpenStack / Linux） | `k8s/README.md` 等对应手册的预检/排错章节 |
| 一天的集中踩坑 | `docs/踩坑总复盘.md`（按阶段分区） |
| 首次完成某模块全流程 | `docs/YYYY-MM-DD-<主题>.md`（完整实验记录） |
| 计时 / 练熟数据 | `docs/k8s-rounds.md` 等曲线表 |

## ② 总结（每日必产出）

`docs/daily/YYYY-MM-DD.md`，固定五段：

1. **一句话** —— 今天的核心成果
2. **里程碑表** —— 做成了哪几件，✅/⬜
3. **踩坑表** —— 现象 → 教训（不复述全文，只留要点）
4. **今日新悟** —— 价值最高的一条认知
5. **明日计划** —— 待办清单

## ③ 存档（工作区记忆）

写入 `C:\Users\l\WorkBuddy\<workspace>\.workbuddy\memory\YYYY-MM-DD.md`：

- 里程碑、版本号、IP/拓扑等**环境变量**
- 当天的教训与后续 TODO
- 跨会话有价值的事实；临时中间产物不写

## ④ 发布

由用户自己在宿主机 PowerShell 执行（沙箱 commit 不可靠）：

```powershell
cd D:\GitHub\cloud-competition-prep
git add .
git commit -m "<type>: <今天做了什么>"
git push
```

**commit 命名约定**：

| 类型 | 场景 |
|---|---|
| `docs:` | 实验记录、总结、曲线表 |
| `k8s:` / `ceph:` / `openstack:` | 对应技术模块 |
| `fix:` | 修正文档或模板错误 |
| `init:` | 仓库骨架类 |

> 推不动时（SSL / proxy 报错）：先 `git -c http.https://github.com/.proxy= push`，或开 Clash 重试。

---

## 三条铁律

1. **当天做，不隔夜** —— 隔夜的细节会失真，回补的成本比当时写高十倍
2. **不美化，只求真** —— 半成品的真实记录比事后补的精致总结值钱
3. **索引同步** —— 新文档必须同步进 README 的索引表，否则 GitHub 上找不到
