## 今日新悟（两条考场级）

### ① daocloud 镜像站的域名映射表（今天的最大发现）

> **不同上游 registry 用不同子域，不能乱拼路径！**

| 上游 | daocloud 域名 |
|---|---|
| docker.io | `docker.m.daocloud.io` |
| **registry.k8s.io** | **`k8s.m.daocloud.io`**（今天的主角） |
| gcr.io | `gcr.m.daocloud.io` |
| ghcr.io | `ghcr.m.daocloud.io` |
| quay.io | `quay.m.daocloud.io` |

错误拼法（`docker.m.daocloud.io/registry.k8s.io/...`）= 403 / not found。
用对域名（`k8s.m.daocloud.io/ingress-nginx/controller:v1.11.3`）一把过。

### ② Ingress 三要素

> **规则（host/path）+ 后端（service）+ `ingressClassName`，缺一个就是 404。**
>
> `kubectl create ingress` **不自动加 class**（坑）！必须 `--class=nginx`。
> 排查口诀：**先查 class → 再查 path → 最后查 service**。

## 方法论沉淀

- **镜像源轮换闭环**：① 先 `curl -m 6 -sI https://站/v2/` 测连通（401/302=正常）② 再 `describe pod` 看真实报错（403=拒绝/not found=没有/timeout=连不上）③ 按结论换源或换域名格式
- **`crictl pull` 直接测试**：不走 kubectl，直接验证"VM 能否拉到这个镜像"，比 apply 后看状态快
- **拉成功后镜像进 containerd 本地仓库**，kubelet 的 IfNotPresent 策略直接使用——**本地化 = 永久免疫外网问题**
