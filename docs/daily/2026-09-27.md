## 当天问题梳理（白话版，复盘用）

> 今天的目标其实只有一件事：**把昨天做好的集群推倒，重新完整地搭一遍，并计时**。
> 结果过程里连撞 4 次"体检没过"，下面按时间顺序逐个讲清楚。

### 时间线与四个坑

```
reset 清空 ──①── init没跑就验收 ──②── master1体检被拦 ──③── worker体检被拦 ──④── master2/3体检被拦 ── 成功
           ⟩ kubectl 报错      ⟩ ip_forward=0      ⟩ 只修了1台       ⟩ 漏带Mem豁免
```

### ① `connection to the server localhost:8080 was refused`

**白话**：kubectl 想去看集群状态，但它"没戴帽子"（没有 `~/.kube/config` 配置文件），只好去默认地址 `localhost:8080` 找，那里什么都没有。

**为什么会这样**：init 还没成功就跳去跑了验收命令。集群压根不存在。

**记住**：**② 必须看到 `initialized successfully` 才能进 ③**，这是铁律。

### ② `[ERROR FileContent--proc-sys-net-ipv4-ip_forward]`

**白话**：`ip_forward` 是 Linux 的"数据包中转开关"，K8S 的网络转发必须开。昨天它是 `1`，**但昨晚 VM 关机，这个值退回 `0` 了**。

**为什么会这样**：两条并存——
- `sysctl -w` 是**临时生效**（重启就没）
- 写进 `/etc/sysctl.d/k8s.conf` 理论上应该开机自动生效，但实测这几台机器重启后没应用上去

**结论**：**每次开工前先跑预检**（已写进手册第九节），别等 init 报错才发现。

### ③ worker1 join 时同样的错

**白话**：我给你修 **master1** 的命令，**只跑了 master1 一台**——但 4 台机器昨晚都关机了，**worker1 / master2 / master3 全都需要修**。

**记住**：批量操作用一条命令循环 4 台，不要手工逐台（逐台一定会漏）。

### ④ `[ERROR Mem]: RAM 1424MB < 1700MB`

**白话**：K8S 要求控制节点至少 1700MB 内存，我们每台 VM 只给 2G，系统实际可用约 1424MB。

**为什么会这样**：join 文件里**漏了 `--ignore-preflight-errors=Mem`**（今天重新生成命令时没带上）。

**记住**：**生成的命令必须看尾巴**——肉眼确认参数齐全再投递。这是今天的第二次同类错误。

### 秒表为什么会丢

`$sw` 是 PowerShell **当前窗口里的临时变量**。中途我让你"回宿主机 PowerShell"，你开了新窗口——**新窗口不认识老窗口的变量**，所以成了 null。

**解法**：计时改成**写文件**（`Get-Date > D:\K8S\timer.txt`），换窗不丢（已写进手册）。

### 一句话总结今天的教训

> **四次失败全部发生在同一个环节：`preflight`（体检）。**
> 而它们的共同根因也相同：**开工前的准备工作没做全**。
> 所以明天的流程不能改 —— **先预检，再动手**。预检 2 分钟，省 10 分钟排错。
