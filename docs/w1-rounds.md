## 已沉淀的经验

1. **plan = 预演，apply / destroy = 真执行**（第 2 轮卡壳点）
   `plan -destroy` 只做推演、什么都不删。**但 `terraform destroy` 本身就自带销毁预演**——
   执行时会先列出 "9 to destroy" 再要你输 yes。所以单独跑 `plan -destroy` 是可省的一步，
   **省掉的前提是：必须读 destroy 自带计划里的数字，确认是 9 不是 0，再输 yes**。
2. **Terraform 幂等**（第 1 轮发现）：资源已存在且与配置一致时，重复 `apply` → `No changes`，
   不会重复建。考场不确定建没建过，重跑一遍 apply 即可确认。
3. **公网 IP 会复用**：多轮同号 `8.149.236.11`（同地域同可用区，释放的 IP 回池再分配）。
   → **IP 不是资产，资源销毁即归零**，识别资源靠实例 ID（`i-bp1...`），不靠 IP。
4. **"下限"是估出来的，不是真的**（第 2c 轮教训）：40 → 4.8 → 3.1 → 2.1 分钟，
   每次宣称"到底了"都被下一轮打脸。真正不可压的只剩 apply 和 destroy 各约 1 分钟的
   云厂商物理时间——**手速部分已经归零，时间曲线到此为止**。
