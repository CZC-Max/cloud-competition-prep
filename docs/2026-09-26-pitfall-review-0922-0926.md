## 一、Windows 环境与版本管理

### 坑 1：winget 装 GitHub CLI 报 `0x80072efd`

| | |
|---|---|
| **现象** | winget 能搜到 gh 2.101.0，但下载时报"意外错误" |
| **原因** | 包*信息*在微软 CDN，安装包*本体*托管在 GitHub Releases，下载被 302 到 `objects.githubusercontent.com`，国内直连被掐 |
| **解法** | 绕开 winget，直接用华为云镜像： `https://mirrors.huaweicloud.com/git-for-windows/` |
| **考场启示** | 国内装任何 GitHub 托管的东西，先想镜像站 |

### 坑 2：镜像站文件名猜错 → 404

| | |
|---|---|
| **现象** | 按常规命名 `Git-2.55.0-64-bit.exe` 下载，返回 404 |
| **原因** | openEuler / Git-for-Windows 的实际文件名是 **`Git-2.55.0.5-64-bit.exe`**（多一个补丁号） |
| **解法** | **别猜文件名，先拉目录清单**看真实文件名（WebFetch 读目录页即可） |
| **考场启示** | 下载前先验存在性，别靠命名规律脑补 |

### 坑 3：openEuler root 密码三重校验

| | |
|---|---|
| **现象** | `123` 太短 → `12345678` 字符类型不足 → `Root@123` 字典词检测不过（**点 N 次完成都没用**） |
| **原因** | Anaconda 系安装器要求：**≥8 位 + ≥3 种字符类型 + 非词典词** |
| **解法** | 用不含英文单词的组合：`Hg2026@K8s`（大写+小写+数字+符号=4 类，11 位） |
| **考场启示** | "点两次完成"只对"弱密码警告"有效，**长度和字典检查是硬卡** |

### 坑 4：`commit -a` 收不到新文件

| | |
|---|---|
| **现象** | `git commit -a -m "..."` 后提示 `Untracked files: xxx.md`，文件没提交 |
| **原因** | `-a` 只提交**已跟踪**文件的修改，**新文件必须先 `git add`** |
| **解法** | `git add .` → `git commit -m` → `git push`（老三样） |
| **考场启示** | 顺手发布闭环 = 这三步，缺一不可 |

### 附：github.com 走代理的正确姿势

```powershell
# 站点级代理（只对 github.com 生效，不影响其他流量）—— 永久配置
git config --global http.https://github.com/.proxy http://127.0.0.1:7897

# 单次绕代理（Clash 没开时用）
git -c http.https://github.com/.proxy= push
```

> 报错里出现 `over proxy 127.0.0.1` = **代理软件没开**，不是网络问题。

## 二、阿里云 Terraform（已归档经验）

### 坑 5：`destroy` 报完"完成"，云端留 9 个孤儿资源

| | |
|---|---|
| **现象** | `terraform destroy` 输出后就关窗；之后发现云端资源还在持续计费 |
| **原因** | `main.tf` 只有 `terraform{}` 块、**没写 provider region**，region 全靠环境变量，关窗即丢失 → 跑错地域 |
| **解法** | ① 模板里显式写 `provider "alicloud" { region = var.region }` ② **销毁后三看** |
| **考场启示** | **报"完成" ≠ 真没了**。三看：① `plan -destroy` 数量对 ② `state list` 必须空 ③ 控制台复核 |

### 坑 6：以为 `plan -destroy` 就是销毁了

| | |
|---|---|
| **现象** | 跑完 `terraform plan -destroy` 就去查 `state list`，发现资源还在 |
| **原因** | `plan` 系列**只是预演**，输出里 `-> null` 是"如果销毁会怎样"的预览 |
| **解法** | 完整顺序：`plan -destroy`（预演）→ `destroy`（真删）→ `state list`（验空）→ 控制台复核 |
| **考场启示** | plan = 预演 / apply、destroy = 真执行。**`destroy` 自带计划，必须读那个数字：显示 9 才输 yes，显示 0 立刻停手** |

### 坑 7：练熟曲线被自己的"极限判断"打脸

| | |
|---|---|
| **现象** | 我判断 3.1 分钟是"云资源物理时间下限"，用户实测压到 **2.1 分钟** |
| **原因** | 我漏算了：`destroy` 自带销毁计划，**省掉单独的 `plan -destroy` 不损失安全性** |
| **解法** | 保留安全红线（读 destroy 自带计划的数字），砍掉冗余步骤 |
| **考场启示** | **任何"这是极限"的说法，实测之前都只是假设** |

### 坑 8：免费试用实例 ≠ 在花钱

| | |
|---|---|
| **现象** | 以为停着的试用机还在扣云盘费，准备释放并提现 |
| **原因** | 误判：试用额度 300 元独立于现金余额，9 元已用额度扣的是**试用金** |
| **解法** | 看控制台"ECS 实例及系统盘免费额度"页确认；现金余额与试用额度互不影响 |
| **考场启示** | 云账单要分清**免费额度 / 现金余额 / 代金券**，三类钱的规则完全不同 |

## 三、openEuler 装机与 Linux 基础

### 坑 9：静态 IP 配了没生效（nmtui 字段没展开）

| | |
|---|---|
| **现象** | nmtui 里把 IPv4 改成 `<Manual>`，保存后 `ip addr` 还是 DHCP 地址、带 dynamic |
| **原因** | Manual 只是"模式"，**必须再按 `<Show>` 展开**才有 Addresses/Gateway/DNS 三个输入框 |
| **解法** | 改命令行更稳：`nmcli con mod ens33 ipv4.method manual ipv4.addresses x.x.x.x/24 ipv4.gateway x.x.x.2 ipv4.dns 223.5.5.5 && nmcli con up ens33` |
| **考场启示** | **`nmcli` 比 `nmtui` 更适合考场**（可脚本化、可粘贴）。有无 dynamic 字样 = 判断静态生效的标志 |

### 坑 10：接口名猜错（`ena33` vs `ens33`）

| | |
|---|---|
| **现象** | `ip addr show ena33` 报错/无输出 |
| **原因** | 看错字符，VMware 虚拟网卡标准是 **`ens33`**（e1000 驱动） |
| **解法** | 接口名不确定时：**先 `ip addr`（不带参数）看全部**，别猜 |
| **考场启示** | 接口名可能是 ens33/eth0/enp0s3，先看再操作 |

### 坑 11：nmtui 界面被内核日志刷花

| | |
|---|---|
| **现象** | 激活网卡时屏幕被 `Link is Down / Link is Up` 刷满，看不到界面 |
| **原因** | 内核日志直接打印到控制台 |
| **解法** | 一条命令让内核闭嘴：`dmesg -n 1` |
| **考场启示** | 遇到 TUI 界面被刷屏就用这招，也是 Jam 排障小技巧 |

### 坑 12：`ping` 通 ≠ TCP 通

| | |
|---|---|
| **现象** | openEuler 官方源报 `Curl error 7 / 35`，但 ICMP ping 正常 |
| **原因** | `repo.openeuler.org` 的 TCP 80/443 被干扰（ICMP 放行 ≠ TCP 放行） |
| **解法** | 换华为云镜像一条 sed：`sed -i 's#http://repo.openeuler.org#https://mirrors.huaweicloud.com/openeuler#g' /etc/yum.repos.d/openEuler.repo` |
| **考场启示** | **排错要分层**：能 ping 不代表能下载，单独测 TCP/HTTPS |

### 坑 13：中文输入法把引号变弯 ❗ 高频

| | |
|---|---|
| **现象** | 手敲 repo 文件后 `dnf makecache` 报 `failed loading ... skipping`；grep 命令"没报错但没输出" |
| **原因** | 中文输入法状态下敲引号 = **弯引号 “ ”**，INI/YAML 解析直接崩，shell 把它当普通字符 |
| **解法** | ① 输入法切英文再敲 ② 能省就省：`echo [kubernetes] > file`（repo 文件引号本就可选） ③ `cat -A 文件` 可实锤（看到 `M-bM-^@M-^\`） |
| **考场启示** | **所有命令里的引号必须是英文直引号**。这是你这五天最贵的坑，栽了不下三次 |

### 坑 14：Windows 复制粘贴带 `\r` 不可见字符

| | |
|---|---|
| **现象** | 粘贴后执行报 `bash: $'v\r': command not found` |
| **原因** | Windows CRLF 行尾符混进 Linux shell |
| **解法** | 粘贴长命令前后留意首尾是否有多余字符；能用变量管道就不手抄 |
| **考场启示** | 和弯引号是同一类问题：**看不见的字符最有杀伤力** |

## 四、VMware 虚拟机运维

### 坑 15：多台虚拟机不能同时开机 ❗ 结构性

| | |
|---|---|
| **现象** | 单开任意一台正常，开第二台必报"未能启动虚拟机"（信息量为零） |
| **原因** | 克隆时 4 台文件**全挤在同一目录**，而每台运行时都要写同名的 `vmware.log` → 后开的拿不到锁 |
| **解法** | **一台 VM 一个独立目录**：把 .vmx/.vmdk/.nvram 等全部搬进各自子文件夹 |
| **考场启示** | 通用规律：**两个服务抢同一个日志文件锁，后启动的必挂**。这条在服务端排障同样成立 |

### 坑 16：删 `.lck` 锁文件必须先完全退出 VMware

| | |
|---|---|
| **现象** | 删除锁文件失败，退出码 1 |
| **原因** | VMware 界面开着，甚至 **`vmware-tray` 托盘进程**还在抓着文件 |
| **解法** | 先确认无 `vmware-vmx`，再 `Stop-Process vmware-tray`，然后删锁 |
| **考场启示** | **VM 运行时删锁 = 拔氧气管**。顺序：关机 → 退程序 → 清锁 |

### 坑 17：克隆后的"身份"

- 开机弹「我已移动 / 我已复制」→ **选「我已复制」**（VMware 重生成 UUID/MAC，等价于重置身份）
- 克隆机必须做**出厂五连**：改 IP → `nmcli con up` → 改 hostname → **重置 machine-id** → reboot

```bash
rm -f /etc/machine-id && systemd-machine-id-setup
```

> 不重置 machine-id：DHCP 撞 IP、证书互顶、join 失败三连击。

### 附：VMware 向导路径的手敲陷阱

位置栏手敲 `D:\K8S\master1\`（**尾部反斜杠**）→ "无效的路径"。
正确姿势：**位置选父文件夹，VMware 自动用「名称」建子目录**。

## 五、Kubernetes 集群搭建

### 坑 18：containerd 两处不改，init 必挂

```bash
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sed -i 's#sandbox_image = .*#sandbox_image = "registry.aliyuncs.com/google_containers/pause:3.9"#' /etc/containerd/config.toml
```

- `SystemdCgroup = true`：cgroup 驱动与 kubelet 对齐，不改 → kubelet 起不来
- pause 镜像换国内源：不改 → init 卡死在拉 `registry.k8s.io`

### 坑 19：flannel CrashLoopBackOff —— br_netfilter 没持久化 ❗

| | |
|---|---|
| **现象** | 节点一直 NotReady，flannel Pod 重启多次进 CrashLoopBackOff |
| **日志原文** | `Failed to check br_netfilter: stat /proc/sys/net/bridge/bridge-nf-call-iptables: no such file or directory` |
| **原因** | `modprobe br_netfilter` **只对本次运行有效**，重启就没了 |
| **解法** | `modprobe` + 写 `/etc/modules-load.d/k8s.conf` + 删 Pod 让 DaemonSet 重建 |
| **考场启示** | K8S 装机头号失分点。**同理适用于 `sysctl -w`：不落盘重启回原样** |

### 坑 20：跨层传命令，别用 awk ❗

| | |
|---|---|
| **现象** | 提取 certificate-key 时 awk 报 `unexpected newline or end of string`，`$KEY` 变空 |
| **连锁反应** | kubeadm 把下一个参数 `--ignore-preflight-errors=Mem` 当密钥值 → `certificate key decoding error: invalid byte U+002D` |
| **原因** | PowerShell → ssh → bash → awk **四层引号嵌套**，awk 的 `{print $NF}` 被绞碎 |
| **解法** | 用**无引号**的 grep 模式 + 空值校验：`grep -Eo "[0-9a-f]{64}" \| head -1`，再 `[ -z "$KEY" ] && exit 1` |
| **考场启示** | 管道穿越层级时，优先选不带引号的语法；**任何取值的变量都要防空** |

### 坑 21：没有 controlPlaneEndpoint 不许加控制面 ❗ 考点本身

| | |
|---|---|
| **现象** | `--control-plane` join 被拒：`unable to add a new control plane instance to a cluster that doesn't have a stable controlPlaneEndpoint` |
| **原因** | init 时没指定 `--control-plane-endpoint`，新 master 不知道该指向谁 |
| **解法（事后补救）** | 导出 cm → 插入 endpoint → 回传： `kubectl -n kube-system get cm kubeadm-config -o jsonpath='{.data.ClusterConfiguration}' > cc.yaml`；`sed -i '1i controlPlaneEndpoint: 192.168.184.11:6443' cc.yaml`；`kubeadm init phase upload-config kubeadm --config cc.yaml` |
| **考场启示** | **init 那一刻就带 `--control-plane-endpoint=<VIP>:6443`**（VIP 由 Keepalived/kube-vip 托管——赛题里 Keepalived 的用途就在这）。事后补能救，但题目要 VIP 就得重签证书 |

### 坑 22：手抄 64 位 hash 必丢字符

| | |
|---|---|
| **现象** | join 报 "hash 要 64 位"，实际粘的是 63 位 |
| **解法** | **零手抄**：现场生成 + 变量管道投递 `kubeadm token create --print-join-command` → `$cp` → `ssh <node> $cp` |
| **考场启示** | 长随机串（hash / certificate-key）**一律现场生成管道传递**，不背也不抄 |

### 坑 23：init / join 的手敲三连翻车

真实发生过的三次：

1. 行首 `--` 被吞 → `kubeadm: Unknown command`（bash 把参数当新命令）
2. `google_containers` 打成 `goole` → 拉不到镜像
3. 长命令被拆三段分别执行 → 后半段报 `No such file or directory`

> **根本解法**：SSH 免密 + 变量管道，或使用宿主终端粘贴。
> **要背的其实只有 3 条短命令**：`kubeadm init --pod-network-cidr=... --image-repository=...` / `kubeadm token create --print-join-command` / `kubeadm join <上一条输出>`。

### 附：join 后短暂 NotReady 是正常剧本

flannel DaemonSet 要在新节点上起 Pod，**等 1~2 分钟**。可用 `kubectl get pod -n kube-flannel -o wide` 确认每个节点都有一个 Running。

## 六、通用排错方法论（这五天沉淀的原则）

### 原则 1：先看现象，再分层定位

遇到"连不上"，按层拆：

```
物理/电源层  → 机器开机了吗？（Destination Host Unreachable = 对方不在网上）
网络层      → ICMP 通吗？（ping）
传输层      → TCP 80/443 通吗？（curl -m 5；ping 通 ≠ TCP 通）
应用层      → 服务在监听吗？（ss -tlnp）
配置层      → 日志说什么？（journalctl -xeu 服务名）
```

> `Host Unreachable`（上线＝不存在）和 `Request timed out`（在线但不响应）是两种病，别混着治。

### 原则 2：报错看最后一行，往往直接点名

flannel 崩溃、certificateKey 解码失败、缺少 controlPlaneEndpoint——三个问题的根因全写在**输出的最后一行**里。别急着猜，**先把完整报错读完**。

### 原则 3：看不见的东西最有杀伤力

| 隐形杀手 | 症状 |
|---|---|
| 中文弯引号 `“ ”` | 命令"没报错但也没效果"、配置文件加载失败 |
| Windows `\r` 换行符 | `command not found`、参数莫名多出字符 |
| 跨层引号绞碎 | awk/sed 语法报错，变量变空 |
| 未落盘的内核参数 | 重启后失效 |
| 同 trial 的日志文件锁 | 第二个实例启动失败 |

**对策：验证要多一步** —— 改完配置 `cat`/`grep`/`systemctl status` 亲眼确认，不要相信"敲了就等于生效了"。
